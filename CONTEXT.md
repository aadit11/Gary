## Integration notes

Things another person needs to know to build on your work: signature changes, new env vars, return-shape changes, mount paths. Remove a note once it is reflected in AGENTS.md.

- **Python 3.12 and `mcp<2`.** `mcp` 2.x renamed FastMCP; the repo pins 1.x so `from mcp.server.fastmcp import FastMCP` works as documented. `uv sync` picks 3.12 automatically (3.14 is too new for some deps).
- **Every tool takes `user_id: str` as its first parameter.** The voice adapter (Person 1) should inject the caller's user id into every function call, so the LLM never has to know it. `DEMO_USER_ID` in `.env` is that id for the demo.
- **MCP mount paths** are `/mcp/checkins/mcp`, `/mcp/money/mcp`, `/mcp/orders/mcp`, `/mcp/mobility/mcp` (streamable HTTP). `mcp_servers.streamable_http_url(base, name)` builds them. `SERVERS` in `mcp_servers/__init__.py` is the registry.
- **Tool results are `speak()` JSON strings**: `{"say": ..., "action_id"?: ..., "data"?: {...}}`. The adapter should hand the whole string to Deepgram; the prompt tells the agent to speak only `say` and pass `action_id` to `confirm_*`.
- **Pending actions**: `pending.create(action_type, user_id, **payload)` in `prepare_*`; `pending.consume(action_id, action_type, user_id)` in `confirm_*`. `consume` raises `PendingActionError` with a speakable `.say`; catch it and `speak(err.say)`.
- **Policy**: `policy.check(kind, payee, amount, user_id, message_text=None)` returns `Decision(needs_approval, reason, family_name)`. Call it inside every money-moving tool.
- **Approvals**: `approvals.request(user_id, action, payload, reason, summary=None)` texts the approver. When the family replies YES, `webhooks/sms.py` resolves it, runs `ACTION_EXECUTORS[action]` **first**, sets `approval.outcome` (`executed` | `failed`), and only then fires the `approvals.register()` callbacks, so the live call never hears about a payment before it happened. `approvals.find_pending(user_id, action, **payload_match)` avoids texting the family twice. Put `summary` ("pay $84.20 to City Electric") and `done_say` ("I paid $84.20 to City Electric.") in the payload; `voice/injection.py` speaks them.
- **Family messaging channel**: `notify.send_sms(to, body)` sends on `FAMILY_CHANNEL` (`whatsapp` for the demo, `sms` once 10DLC clears). `_can_message` refuses empty, non-US, and area codes 500 and 555 before any Twilio call. Inbound WhatsApp replies arrive at the same `/webhooks/sms` route; `From` comes in as `whatsapp:+1...` and `normalize_phone` handles it.
- **Voice call parameters**: TwiML `<Stream>` carries `user_id`, `reason` (`inbound` | `reminder` | `appointment` | `morning_briefing`), `reminder_text`, and `reminder_id` on reminder calls. `voice/agent_settings.py` picks the prompt, greeting, and which MCP servers to expose per reason (`SERVERS_BY_REASON`). Inbound exposes `checkins`, `money`, and `orders`; reminder and appointment expose only `checkins`. Another language is a new `VOICES` entry, not a bridge change.
- **MCP adapter transport**: `MCPAdapter()` defaults to in-process sessions over the same FastMCP objects (no loopback HTTP; uvicorn isn't listening yet during lifespan startup). `MCPAdapter(transport="http")` uses real streamable-HTTP sessions. Schemas are identical either way.
- **Live-call injection**: `voice.bridge.ACTIVE_SESSIONS[user_id]` is the live session; `voice/injection.py` is registered with `approvals.register()` and speaks the family's decision with `InjectAgentMessage` (`behavior: interrupt`).
- **Outbound calls**: `voice.twilio_routes.place_outbound_call(user_id, reason, reminder_id=None, note=None)`. `note` becomes `reminder_text` on the stream (used for the appointment prompt). Twilio fetches `/voice/outbound-twiml?...` which returns the same stream TwiML. `dial_number(call_sid, phone)` replaces the live call with `<Dial>` and returns false for numbers `_can_message` rejects.
- **Twilio number webhooks** (run `uv run python scripts/set_twilio_webhooks.py` after every ngrok restart): voice -> `PUBLIC_BASE_URL/voice/incoming`, SMS -> `PUBLIC_BASE_URL/webhooks/sms`. WhatsApp sandbox inbound URL is set in the console.
- **Browser agent**: `from browser_agent.runner import BrowserJobRunner`; `app.state.browser_runner.submit(site, goal, user_id=..., flow_key=..., on_done=fn)` where site is `dashdish` or `udriver`. Pass `flow_key` (e.g. the favorite's id) to learn the flow on first success and replay it next time (`backend/data/flows/<site>/<key>.json`, committed). The model emits multi-step plans; `click_named(role, regex)` etc. act on elements not yet on the page. `on_done` runs on the worker thread; use `asyncio.run_coroutine_threadsafe` to touch the call loop (see `voice/injection.py`). Goals are plain English; `browser_agent/tasks.py` appends a short per-site flow hint. `MUSE_REASONING_EFFORT=low` (a reasoning model; `minimal` is faster but sloppier). `BROWSER_USE_SCREENSHOT=false` is ~25% faster.
- **REAL clone facts**: DashDish checkout uses the clone's own saved address and card (Foster City, Visa ...5097); do not ask the agent to change them. Udriver only accepts pickup/dropoff from its own place list (substring search); pick places that exist there.
- **Web env**: `web/next.config.mjs` reads the repo-root `.env` and exposes `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `DEMO_USER_ID` as `NEXT_PUBLIC_*`. `allowedDevOrigins` includes `127.0.0.1` so the dev server accepts that host. On Vercel set the `NEXT_PUBLIC_*` vars directly.
- **Caregiver profile**: one `emails` row, `gmail_id` exactly `caregiver-profile`, `classification=other`, so appointment tools ignore it. `extracted` holds `dietary`, `expenses` (`category`, `due_day` 1–28, `active`), `notify_expenses`, `connectors` (`doordash.usual`, `uber.home`, `uber.hospital`, `groceries.store`, `banking.connected` for bill reminders only), `weekly_days` (reminder id → weekday, Monday=0), and `onboarded`. The desk writes it with the anon key (`PUT /api/profile`, and weekly days from `POST /api/reminders`). The scheduler reads it. A demo profile is already saved for Margaret: rent due on the 1st, low sodium, chicken soup and tea, home at 12 Oak Lane, Springfield General, and Sunrise Market. Do not store card numbers, passwords, or bank logins. Expense categories: rent, utilities, groceries, pharmacy, phone, insurance. Diet presets include low sodium, diabetic-friendly, soft foods, no nuts, vegetarian, gluten-free, and lactose-free. Gary does not suggest a dose or a diet change.
- **Google ingest**: `uv run python scripts/google_oauth.py` once (Testing-mode OAuth), then `scripts/seed_gmail.py` to insert `X-Gary-Seed` messages + doctor Calendar event, then `scripts/ingest_gmail.py` to classify into `emails` / `bills`. Re-ingest is safe. `google.calendar.list_upcoming()` is ready for Person 1's briefing tools. Local package `backend/google/` shadows the Google API namespace — use `google._thirdparty.load()` (already wrapped by `auth.py`) for Credentials/build.
- **Console testing without a call**: `uv run python scripts/chat_gary.py` (from `backend/`) runs the lifespan in-process with the reminder scheduler off (`GARY_NO_SCHEDULER=1`), opens a real Deepgram agent session through `voice/bridge.py` with a fake Twilio socket, and turns typed lines into `InjectUserMessage`. Same model, prompt, tools, and injection path as a phone call; replies print as text. `--reason reminder --reminder-text ...` for outbound personas.
- **Restaurant lookups**: status is keyed by a normalized name (`_normalize_restaurant`), so "Souvla", "the Souvla restaurant", and "Souvla place" share one lookup; a second mention while checking no longer cancels the job, and a cancelled lookup clears its status so a retry works. Lookup ~24 s (multi-action plans); order on the parked page ~15-20 s.
- **Fake database for tests**: `tests/conftest.py` forces `GARY_FAKE_DB=1` and provides a `demo` fixture with a user, approver, known payees, and bills. Write your tool tests against it; no network needed.
- `backend/pyproject.toml` lists dependencies by name without pins. Run `uv sync` once and commit the lockfile.
- `web/package.json` uses `latest` for all packages. Run `npm install` once and commit the lockfile.

## Known issues and blockers

- The browser agent's DashDish total varied between runs ($21.77 vs $23.37) because it sometimes picks a different size option; the read-back should quote the item, not a precise total, until the agent reports it.
- **SMS is blocked on our Twilio number** (carrier error 30034: local 10DLC number without A2P registration; registration takes days). Family messages go over the **Twilio WhatsApp sandbox** instead (`FAMILY_CHANNEL=whatsapp`). Any phone that should receive approvals must first send `join halfway-rate` on WhatsApp to +1 415 523 8886. The seeded caregiver number is the invalid test number `+15005550001`, so family texts, regular-bill reminders, and caregiver dials no-op until a real number is put back. +1 315 480 4465 can still receive voice calls.
- The ngrok URL changes on every restart (free plan). When it does: update `PUBLIC_BASE_URL` in `.env`, restart the backend, run `scripts/set_twilio_webhooks.py`, and update the WhatsApp sandbox "When a message comes in" URL in the Twilio console (no API for that one).
